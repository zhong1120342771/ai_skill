# 上下文检索剧本

当需求涉及存量业务、系统、接口、数据、权限、流程、状态或规则时，必须基于可用工具查询公司上下文。

## 检索来源类型

### 业务知识源

历史 PRD、知识库、运营规则、客服口径、项目复盘、决策记录。

### 研发知识源

当前线上实现、MCP / 代码查询、接口文档、服务说明、技术设计、数据库 schema、配置中心。

### 数据知识源

数据字典、埋点平台、BI 指标、数仓口径、实验平台。

### 质量与历史问题源

测试用例、缺陷系统、线上事故、客诉记录。

## 事实类型与来源矩阵

| 事实类型 | 优先来源 | 辅助来源 | 说明 |
|---|---|---|---|
| 当前业务逻辑 | 当前线上实现 / 代码 / 接口 | 历史 PRD / 知识库 | 历史 PRD 不能单独作为当前事实 |
| 状态流转 | 代码 / 接口 / schema | 历史 PRD | 冲突时标记冲突 |
| 字段约束 | schema / 接口 / 代码 | 历史 PRD / 数据字典 | 不臆造字段类型 |
| 兼容边界 | 代码 / 接口 / 线上行为 | 历史 PRD / 事故复盘 | 涉及老数据需说明 |
| 业务术语 | 历史语料 / 知识库 | 当前输入 | 当前输入与标准术语冲突时，优先标准术语 |
| 章节结构 / 表格范式 | 历史语料 | 当前输入 | 用于风格，不用于证明当前逻辑 |
| 本次目标 / 范围 | 当前输入 | 业务知识源 | 用户当前输入决定本次目标 |

## 检索结果标准化

| 信息点 | 来源 | 时间/版本 | 可信度 | 与本需求关系 | 是否冲突 |
|---|---|---|---|---|---|

## 历史语料使用边界

- 历史 PRD / 历史语料用于术语、结构、范式、历史背景；
- 不得单独作为当前业务逻辑依据；
- 与当前线上实现、接口、schema、代码冲突时，必须标记冲突；
- 如本次需求主动改变历史逻辑，应说明是主动变更，并写明兼容、风险、验收。

## 来源冲突处理

默认可信优先级：

```text
当前线上实现 / 当前接口文档 / 当前 schema
>
正在生效的业务规则文档
>
已发布历史 PRD
>
运营口径 / 客服口径
>
会议纪要 / 聊天记录
```

如果高优先级来源不存在，可使用低优先级来源作为 `[假设]`，但不能伪装成已确认事实。

## 查不到存量信息时

查不到不等于一定没有存量逻辑。

- 如果该对象大概率存在存量逻辑，并且会影响方案、研发路径、兼容或验收，标记 `[阻塞]` 或要求确认。
- 如果该对象更可能是增量逻辑，且不影响现有系统，可按新增推进，并说明为 `[假设]`。
- 如果是通用常识或不需要公司特定口径，不必强行追问存量。

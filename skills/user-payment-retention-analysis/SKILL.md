## 分析维度二：支付转化率（D0-D408）

### 输入数据格式

两组数据（转化率 + 单量），均为表格：`用户类型 | 活跃人数 | 0 | 1 | 2 | ... | 408`

- 列 0-408 代表活跃后间隔天数，值为当日支付转化率（%）或支付单量（笔）
- **转化率口径**：支付订单量（不考虑退款）/ 活跃当日 DAU

### 分析要点

1. **核心指标**：D0 当日转化、D0-D7/D30/D90/D180 累计转化、D7/D0 周频比、人均单量、50%/80% 订单集中日

3. **老用户特征**：复购频率高，D7 累计即反超新增，D30 领先 1.7 倍
4. **新媒 vs 自然新增**：D14 后差距趋零，投放优势仅限于首周

## 分析维度三：周波动深析（可选，需明细数据）

### 前置条件

仅当用户提供含`活跃日期`字段的 Excel 明细数据时触发。

### 输入数据格式

Excel（.xlsx），包含字段：`活跃日期 | 用户来源 | 活跃人数 | 活跃后的间隔天数 | 单量`

### 核心方法

用 Python/openpyxl 读取，计算两个维度的支付转化率：

1. **自然周几效应**：`payment_weekday = weekday(活跃日期 + 间隔天数)`，按 0-6（周一~周日）分组求均值
2. **间隔周期效应**：按 `interval % 7` 分组（0=与首次活跃同星期几，6=前一天星期几）

### 关键结论（已验证）

- **自然周几几乎无差异**：周一~周日峰谷比仅 1.06-1.09x → 用户不会因为周五就多付
- **真正的周期来自 interval%7**：D%7=0 转化率最高，逐步衰减至 D%7=5/6。新增用户峰谷比 2.4-2.6x，老用户 1.2-1.4x
- **策略含义**：不是"周一统一推送"，而是按用户首次活跃的星期几做**个性化同日触达**

## 分析维度四：支付用户行为特征挖掘（新增）

### 适用场景

用户提供含用户行为标签的抽样明细数据，要求识别支付转化关键行为信号、定义 Aha Moment 阈值、按来源拆分策略。

### 输入数据格式

CSV（100 万行随机抽样），字段：

| 字段 | 说明 |
|------|------|
| 日期 / dt | 行为发生日期 |
| 用户id / token | 用户唯一标识 |
| 用户来源 / user_source | 四类来源之一 |
| 是否支付用户 / tag | **口径**：活跃后 7 日内是否有下单。paid / non_paid |
| 当日单量 / ord_day0 | D0 支付单量 |
| 7日内总单量 / ord_7days | D0-D7 累计支付单量 |
| 当日收藏次数 / fav_cnt | D0 收藏行为次数 |
| 当日加购次数 / cart_cnt | D0 加购行为次数 |
| 当日点击下单次数 / click_order_cnt | D0 点击下单按钮次数 |
| 当日商详访问次数 / sx_pv | D0 商详页 PV（最核心的行为深度指标） |

### 分析要点

#### 1. 全量分析

1. **支付率总览**：全量支付率，四类来源支付率排名
2. **行为指标对比**：支付 vs 非支付用户在 6 个行为指标上的均值差异（倍差）、非零率差异。点击下单倍差最高（~10x），加购覆盖面最广但区分度最低
3. **商详访问深度梯度**：将 sx_pv 分为 7 桶（0, 1, 2-3, 4-7, 8-15, 16-30, 30+），计算每桶支付率，找到突破 5% 的阈值即为 Aha Moment
4. **多信号组合**：收藏+加购+点击下单的三重信号组合，0/1/2/3 重信号的支付 vs 非支付占比对比
5. **交叉条件精准度**：加购≥3 & sx_pv≥8 等组合条件筛选后的支付率
6. **复购强度**：支付用户 7 日内 1 单 vs 2 单+ 占比

#### 2. 四类来源拆分（关键！）

**每个发现都必须按四类来源拆分**，核心对比维度：

| 对比维度 | 新媒体新增 | 新媒体召回 | 自然留存 | 自然新增 |
|----------|:--------:|:--------:|:------:|:------:|
| 支付率 | 3.4% | **3.8%** 最高 | 2.8% | 2.5% 最低 |
| 支付用户 sx_pv | **38** 最高 | 34 | 23 最低 | 24 |
| 非支付用户 sx_pv | 5.7 最高 | 4.6 | 3.2 | 3.4 |
| 点击下单倍差 | 高-冲动型 | 中-效率型 | 低-习惯型 | 中 |
| 3 重信号占比 | **19%** 最高 | 19% | 16% | 17% |
| 7 日人均单量 | **1.52** 最高 | 1.38 | 1.31 | 1.45 |

**四类用户转化路径画像：**
- **新媒体新增 → 冲动型**：首日 sx_pv 最高，点击下单倍差最大，3 重信号占比最高。"来得猛、走得快"
- **新媒体召回 → 效率型**：支付率最高，加购多但点击下单偏低。"多逛多加购、集中下单"
- **自然留存 → 习惯型**：行为均值全面偏低，但体量最大最稳定。"不需深逛就转化，短平快"
- **自然新增 → 冷启动型**：所有指标垫底，非支付中多信号占比却最高。"有意图，缺临门一脚"

#### 3. Aha Moment 定义

```
sx_pv = 0      → 支付率 0.7%（沉默用户，占 51%）
sx_pv = 1-7    → 支付率 1.4-3.6%（浏览型用户）
sx_pv = 8-15   → 支付率 6.8%（★ Aha Moment，突破 5%，跨来源通用）
sx_pv = 16-30  → 支付率 13.4%（高意向用户）
sx_pv = 30+    → 支付率 30.8%（确定转化，每 3 人有 1 人付）
```

## 分析维度五：自然留存深度挖掘方向（待数据）

当用户需要对自然留存用户进一步深挖时，提出以下三个方向：

### 方向 1：留存深度分层 × 支付转化（推荐 P0）

**假设**：自然留存内部差异大——刚留存 7 天的和留存 2 年的支付行为完全不同。

**所需数据**：用户首次活跃日期 / 注册日期，或用户生命周期阶段标签

**分析问题**：
- 留存 <30 天 / 30-90 天 / 90-180 天 / 180 天+ 各段支付率和行为特征
- 老留存用户是否"逛得少但买得快"？
- 新留存用户是否更像自然新增（需 deeper engagement 才转化）？

### 方向 2：历史支付行为 × 当日行为联动（P1）

**假设**：自然留存是历史支付行为的延续，而非独立事件。

**所需数据**：历史支付记录（最近一次支付日期、历史累计支付单量/金额）

**分析问题**：
- 近 7 天付过 vs 近 30 天付过 vs 30 天+未付，当日行为差异？
- 历史高频用户（月均 2 单+）的当日 sx_pv 是否更低（习惯性购买）？
- 沉默支付用户（30 天+未付但有浏览）的唤醒概率？

### 方向 3：品类偏好 × 转化效率（P2）

**假设**：不同品类的浏览-支付转化效率不同。

**所需数据**：当日浏览/收藏/加购的 info_id（可通过行为日志关联品类）

**分析问题**：
- 手机 vs 潮玩 vs 奢侈品的 sx→支付梯度差异？
- 高客单价品类是否"浏览多但支付率低"？
- 哪些品类是自然留存用户的"入口品类"？

## 飞书文档写入 SOP

### 1. 解析文档 Token

```bash
# Wiki URL → obj_token
lark-cli wiki spaces get_node --params '{"token":"<wiki_token>"}' -q '.data.node'
# 取 obj_token 和 obj_type（应为 docx）
```

### 2. 追加文本内容

```bash
lark-cli docs +update --doc "<doc_token>" --mode append --markdown - < report.md
```

Markdown 中嵌入图片锚点：`[图X: 说明文字]`

### 3. 插入图片（倒序！）

从最后一个锚点往前插入，确保最终顺序正确：

```bash
lark-cli docs +media-insert --doc "<doc_token>" \
  --file ./chart_name.png \
  --selection-with-ellipsis "[图X: 说明文字]"
```

- `--file` 必须用相对路径（先 cd 到文件所在目录）
- 每次插入后文档 block 数量变化，下一个锚点位置自动调整

### 4. 清理锚点文本

```bash
for anchor in '[图X: ...]' '[图Y: ...]' ...; do
  lark-cli docs +update --doc "<doc_token>" --mode delete_range \
    --selection-with-ellipsis "$anchor"
done
```

### 5. 覆盖已有内容

若要替换文档中某 section（如修正数据后重写）：

```bash
# 删除从标题到文档末尾的全部内容
lark-cli docs +update --doc "<doc_token>" --mode delete_range \
  --selection-by-title "## 章节标题"
```

### 6. 插入口径备注

```bash
lark-cli docs +update --doc "<doc_token>" --mode insert_after \
  --selection-by-title "## 章节标题" \
  --markdown "> **口径说明**：..."
```

## 常见陷阱

1. **数据列代表"间隔天数"不是"自然周几"**：D0 是各用户首次活跃当天，不同用户的 D0 可能落在不同星期，不能直接当周一来解读
2. **周波动要用明细数据验证**：不要仅凭 D0-D90 聚合曲线的锯齿就下"周一高周日低"的结论，必须用 `活跃日期 + interval` 计算实际支付星期几来验证
3. **峰谷比口径要写清楚**：是"自然周几峰谷比"还是"间隔%7 峰谷比"，两者含义完全不同
4. **转化率数据可能给错**：运行前先和用户确认口径（是否/DAU？是否含退款？），发现 D0 转化超过 10% 时主动质疑
5. **`--file` 必须相对路径**：lark-cli 不接受绝对路径，先 cd 到文件目录
6. **图片插入顺序是反的**：从后往前插，最终文档才是正序
7. **是否支付用户的口径必须备注**：明确写清楚"活跃后 7 日内是否有下单"，避免与 D0 当日支付混淆
8. **行为特征分析必须按来源拆分**：全量结论掩盖了四类用户的本质差异，每个发现和策略都需拆到四类来源维度

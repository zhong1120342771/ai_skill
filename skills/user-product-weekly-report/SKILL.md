## Step 5: 数据检查

写入完成后，**必须**执行以下检查。检查分两层：快速自检（内联执行）+ 深度质量检查（调用 quality-assurance agent）。

---

### 5.1 快速自检（内联执行）

#### 正确性检查

1. **数据点比对**：随机抽取每个板块的 5-10 个数据点，与源文件逐值比对
2. **wow 计算验证**：抽取 3 个分类，手动计算 wow = last/prev - 1，与输出结果比对
3. **行数校验**：总行数 = 板块1行数 + 板块2行数 + 板块3行数（含标题/表头/分隔/子板块行）
4. **周数完整性**：每个分类应包含 5 个数据周（稀疏分类除外），抽检确认无缺失

#### 格式检查

1. **百分比格式**：率指标列是否已设置 `0.00%` 格式（xlsx）/ `formatter: "0.00%"`（飞书）
2. **整数格式**：DAU/UV/PV 列是否已设置 `#,##0`
3. **wow 行颜色**：xlsx 中 wow 行是否使用 `[Red]0.00%;[Color10]-0.00%`
4. **合并单元格**：分类名列是否正确合并
5. **飞书数据完整**：从飞书读回关键行，确认与源数据一致（而非空值或错位）

#### 修正

如发现错误，自动修正后重新写入。

## Step 6: 数据分析结论

数据检查通过后，基于整理好的数据撰写结构化分析结论，随飞书消息推送。

### 结论组织框架

参考消电618日报的结论写法，结论分以下四个层次组织：

```
【{MMDD} 用户产品周会数据结论】{当周日期范围}

**【核心结论】**
一句话概括本周整体转化表现（涨/跌/持平），点出最主要的驱动因素或拖累项。

---

**【整体大盘】**
- DAU：{绝对值}，wow {±%}，说明趋势（连涨/连跌/回升）
- 净支付PV：{绝对值}，wow {±%}
- DAU净支付PV转化率：{值}，wow {±%}，{涨则说涨在哪个环节，跌则说跌在哪个环节}
- 曝光渗透率：{值}，wow {±%}，{是否持续下滑/回升趋势}
- uv商详到达率：{值}，wow {±%}
- 商详转化率：{值}，wow {±%}
- 净支付提袋率：{值}，wow {±%}

---

**【分用户类型亮点】**
对比四类用户（新媒体召回/新媒体新增/自然新增/自然留存）的 DAU净支付PV转化率和净支付PV，
挑出 wow 涨幅最大和跌幅最大的各1-2个，说明原因方向（如新媒体召回净支付PV环比+X%，可能与XX有关）。

---

**【分品类亮点】**
聚合品类中，挑出本周 DAU净支付PV转化率 wow 涨跌最显著的品类（取绝对值排序，取top2），
各一句话说明：品类名、转化率绝对值、wow变化、净支付PV变化。

---

**【找靓机】**
- 整体：净支付pv {值}，wow {±%}；DAU净支付pv转化率 {值}，wow {±%}
- 手机（最大品类）：净支付pv {值}，wow {±%}；转化率 {值}，wow {±%}
- 其他值得关注的细分品类（如有明显异动）：一句话说明
```

### 撰写规则

1. **数据呈现格式**
   - 率指标保留 2 位小数（如 `1.19%`）
   - 绝对值使用千分位（如 `38,480`、`3,245,503`）
   - wow 正数加 `+` 号，负数保留 `-` 号（如 `+7.70%`、`-2.29%`）

2. **结论方向判断**（wow 基准）
   - DAU净支付PV转化率 wow > +1%：正向，说明转化整体提升，定位涨在哪个漏斗环节（曝光/商详/下单/支付）
   - DAU净支付PV转化率 wow < -1%：负向，说明转化下滑，定位跌在哪个漏斗环节
   - |wow| ≤ 1%：持平，简单带过
   - 曝光渗透率 wow < -3%：需单独标注，提示关注流量入口侧

3. **漏斗拆解逻辑**
   - 转化率涨跌先看 `曝光渗透率`（影响进入漏斗的 UV 量）
   - 再看 `uv商详到达率`（曝光→商详的转化）
   - 再看 `商详转化率`（商详→下单）
   - 再看 `净支付提袋率`（下单→支付）
   - 哪个环节 wow 变化最大，即为主因

4. **文字风格**
   - 简洁直接，不用"我认为"、"可能是"等弱化表述
   - 数据异动要给出方向性解释（"受XXX影响"或"源于XXX环节"）
   - 正向数据可适当加粗，负向异常也加粗

### wow 计算方式（在结论中使用）

```python
# wow = 当周值 / 上周值 - 1
# 取 xlsx 中最后数据行（本周）与倒数第二行（上周）对比
week_cur  = rows[-1]  # 最新周（第24周）
week_prev = rows[-2]  # 上一周（第23周）
wow = week_cur / week_prev - 1
```

### 存放位置与写入方式

1. **在样例目录下建 wiki 子节点**（父节点 token 由用户指定，默认沿用上周父节点）：
   ```bash
   lark-cli wiki +node-create --as user \
     --parent-node-token "<父节点token>" \
     --title "【{当周日期范围}】用户产品周报-ai生成"
   ```
   记下返回的 docx `obj_token`。
2. 用 `docs +update --command append`（文本 XML）与 `docs +media-insert --file … --align center --width 900`（图片，均追加到文末）**按目录顺序**逐段构建。
3. **若是在已有文档上更新截图**：`media-insert` 只能追加到文末，需先把新图 `block_move_after` 到旧图之后，再 `block_delete` 旧图；图片/表格块以 token 存储，替换时避开正文，勿用 `overwrite`。
   - `media-insert` **不接受 `--api-version` 标志**（会报 unknown flag），且必须带 `--type image`；文件路径用 cwd 相对、纯 ASCII 文件名。

   - 每条 lark-cli 命令结尾加 `</dev/null`，否则在 `for`/函数循环里 stdin 会被吞导致只执行一次。
   - 移动+删除后，`fetch --detail with-ids` 按字符位置校验：每张图只剩 1 份、且紧跟在对应小标题之后。

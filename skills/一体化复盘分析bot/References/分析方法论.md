# 分析方法论

复盘的分析框架、剔噪口径、分层规则。所有数字最终经 pandas 重算校验。

## 一、三个问题框架

复盘不是把指标堆一遍，是回答三个业务问题，每个问题给「原始变化 + 剔季节净效应 + 一句判断」。

| 问题 | 主指标 | 剔噪方法 | H1 结论（示例，供口径参考） |
|---|---|---|---|
| 本地需求是否被激发 | 同城订单占比/量 | DiD + 同比 | 试点占比 20.69%→28.36%（+7.67pp），DiD 净 +6.78pp；量 232→423（+82.5%） |
| 小店是否受益 | 线索量/转化、小店同售动销率/单量 | 城市三档 DiD | 线索 35→299（约8.6倍）但转化率被稀释；小店动销率 DiD 净 +0.89pp |
| pro店是否受益 | pro店同售单量/动销率 | 量级判断+城市DiD借用 | pro 96→480（+398.8%，约5倍），动销率 +1.62pp |

写结论的语气：中性克制、不硬塞情绪；能一句话下判断的下判断，需要保留的（如线索"引流成立、收益要盯成交"）明确说保留。

## 二、剔除周期性的两套口径

单看"期末比期初涨了"会把大盘季节波动（春节低、618 高）算进项目效应，必须剔噪。两套口径互证：

### DiD 双重差分（主口径）
净效应 =（试点期末 − 试点期初）−（对照期末 − 对照期初）。
- 对照城市 = 重庆市 + 西安市（H1 内未上线一体化），代表大盘自然季节波动。
- 例：同城占比 DiD = 7.67 − 0.89 = **+6.78pp**；小店同售动销率 DiD = 1.74 − 0.85 = **+0.89pp**。
- 适用：有可比对照组的比率指标。

### 同比（佐证口径）
2026 与 2025 同月对比。2025 是项目上线前基线。
- 例：试点同城占比 2025 H1 平坦（18.77%→20.04%，+1.27pp），2026 爬坡 +7.67pp——同样日历月份去年没爬坡今年才有，指向项目效应。
- 适用：有 2025 基线的指标（同城占比）。同售/线索是项目新增，2025 无基线，改用 DiD 或量级判断。

### 量级判断（无对照/无基线时）
pro 店无 2025 基线、对照组弱，用"量级远超季节波动 + 加速时点对齐业务动作而非大促"来判断。例：pro 单量约 5 倍增长远超任何季节波动，4-5 月加速对齐一期铺开/二期新仓店上线，而非 618。

## 三、日均口径（绝对值指标统一用法）

绝对值指标（订单量、线索量、小时达量、同售单量）**一律用日均**，消除各月天数不等 + 新增能力当月非全月有数据的干扰：

```
月日均 = 当月总量 / 当月有数据的 distinct dt 数
增幅   = 6月日均 / 1月日均 − 1
```

比率指标（占比、动销率、转化率）对量级不敏感，不用日均，照常按月聚合。

通用实现见 `scripts/charts/regen_dailyavg.py`：
```python
def da(df, dcol, valcol, gc=None):
    df[dcol]=pd.to_datetime(df[dcol]); df=df[df[dcol]<=CUT]
    df["month"]=df[dcol].dt.to_period("M").astype(str)
    g=df.groupby(["month"]+(gc or [])).agg(total=(valcol,"sum"), nd=(dcol,"nunique")).reset_index()
    g["日均"]=g["total"]/g["nd"]; return g
```

**⚠️ 拆分时的天数口径陷阱（血泪）**：把整体拆成子项（如小时达拆仓/店）时，**子项不能各自用自己的活跃天数**——稀疏子项（如"其他"订单只在少数天出现）除以自己的小天数会被放大，子项加总 ≠ 整体。正解：**所有子项共用「当月整体活跃天数」**（单一月度 nd），保证 Σ子项日均 = 整体日均。详见踩坑文档。

## 四、分层口径

### 城市三档
- **试点城市** = 成都市 + 郑州市（双城，门店独占期缩短、统一定价、小时达、门店表达全量落地，1 月起全周期生效）。
- **对照城市** = 重庆市 + 西安市（H1 内未上线一体化，作 DiD 对照组）。
- **其他一体化城市** = 除重庆&西安外其余全部（多在 4 月末至 5 月才陆续上线，效果集中在 5-6 月，1-4 月接近未上线）。

> 分层**绝不用源表 abgroup 字段**——城市表里该字段标签过时（只把郑蓉标一体化、其余标非一体化，与实际相反），一律按城市名重打标。

### 门店两类
同售门店只分 `小店` / `pro店`（type_md 字段），且同售门店试点仅郑州&成都。

### 履约来源两侧（仓/店）
同城订单/小时达可按履约来源拆**中心仓 / 门店**，门店再拆小店/pro店：
- 同城订单：需用带 `md_type` 的 0722 版底表（见数据表文档）。
- 小时达：`dws_yth_core_xsd_layer01_zmt_v1_0723_di` 的 `abgroup` 字段实际就是仓/店标记，0723 表取值为 仓库订单/小店/pro/其他（门店已拆 pro/小店；旧 v1_di 只到店铺订单粒度、已弃用），注释"是否一体化城市"是错的。
- 拆分两个互补视角：**单量**看谁盘子大（仓主导 ~90%）、**占比**（该来源同城单/该来源总单）看一体化把谁的本地成交比例拉得更高（门店弹性远高于仓）。结论句式："仓贡献量，门店贡献占比弹性"。

## 五、拆分与整体对齐（两种方法）

拆分子项加总必须严格等于整体口径，否则读者会问"为什么正文写 A→B、拆解图却是 A→C"，产生解释成本。两种对齐方式按场景选：

1. **共用月度天数**（同源底表、只是天数口径问题）：所有子项日均 = 子项当月总量 / **当月整体活跃天数**。Σ 严格等于整体，无需缩放。用于小时达仓/店。
2. **等比缩放**（拆分底表与主口径底表版本不同导致合计有小差）：`scale_m = 整体口径月总量 / 拆分底表月合计`，每档乘以 `scale_m`。用于同城仓/店（0722 表 vs 主 v1 表 5-6 月差几十单）。缩放方式与前提要在正文显式标注。

## 六、季节节点（仅用于解释，不进判定）

客观日历：春节 2 月（大盘总订单走低）、618 大促 6 月（拉高绝对量）。比率指标受促销影响小；绝对量 6 月含 618 放大，需在正文说明。**不把大促窗口/峰日臆造进判定逻辑**——需要就从数据实测，不套行业惯例。

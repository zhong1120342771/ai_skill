# 复盘问答与踩坑

H1 复盘过程里定过的口径决策和踩过的坑。下次复盘遇到同类问题直接照这里，不重复试错。

## 一、口径决策（问答里定下来的）

### pro店同售拆分口径（按城市，非双城/非双城）
- 定：pro 店同售拆分**按城市逐个拆**（郑州/成都/东莞），不再用「双城 vs 非双城」两分。原因：三城分别在不同月上线，城市粒度更能讲清"谁先起、谁接力"。
- H1 事实（共用整体月度天数，Σ 严格=整体 96→480）：郑州基本盘 96→189（约 2 倍，1-3 月唯一有数城市，全程动销率最高 4.72%→8.05%）；东莞 4 月上线 51→133→174（6 月动销率 6.86%）；成都 5 月才起量 53→117（新店库存刚铺、动销率最低 4.35%）。6 月三城约三分：郑州 39%、东莞 36%、成都 24%。结论：整体冲到 480 不是单城放大，是郑州稳基本盘+东莞成都两新城 5-6 月接力上量。
- 图为 `fig9_pro_volume_by_city.py`（按城市堆叠）。旧「全口径 vs 双城」版本已弃用。

### 门店同售"775"口径
- 门店同售单量 245→775（+216.3%）是**一体化影响口径** = pro店全口径 + 小店双城（因为一体化影响的小店只有双城，顺畅固化层即全量）。双城口径为 245→601（+145.0%，pro 只看双城）。两个口径都自洽，用哪个要在文里说明，别混。

### 同城仓/店拆解两个互补视角
- **单量**：中心仓是主引擎（868→1355，+56.2%，6 月占 90.3%，贡献增量 83.7%）；门店基数小增速快（50→145，+187.9%）。
- **占比**（该来源同城单/该来源总单）：门店弹性远高于仓——仓 3.00%→3.92%（+0.92pp），门店合计 3.89%→8.25%（+4.36pp），pro 1.69%→7.58%（+5.88pp，弹性最大）。
- 一句话："仓贡献量，门店贡献占比弹性"。

## 二、踩坑（务必避开）

### 坑1：拆分子项的天数口径（最容易错）
把整体拆成子项算日均时，**子项各自用自己的活跃天数会把稀疏子项放大，加总≠整体**。
- 实例：小时达拆仓/店，"其他"订单只在少数天出现。用各 tier 自己的 nd 算，1 月整体虚高成 23；用统一月度天数算，整体是 20（与原数一致），仓库 15、店铺 4、其他 0。
- **正解**：所有子项 = 子项当月总量 / **当月整体活跃天数**（单一 nd）。Σ 严格等于整体。
- 教训：拆分对不上整体时，先查是不是天数口径问题，再考虑等比缩放。

### 坑2：拆分底表与主口径底表版本差 → 等比缩放
同城仓/店用 0722 表，与主 v1 表某些月合计差几十单（5 月 +52、6 月 +46）。
- **正解**：`scale_m = 主口径月总数 / 0722表月合计`，每档乘 scale_m，使拆解合计严格对齐正文的整体（如 918→1501）。缩放方式与前提在正文显式标注。
- 为什么要对齐：正文写 918→1501、拆解图却 918→1546，读者会问对不上，产生解释成本。

### 坑3：abgroup 字段双义 / 注释骗人
见 `数据表与口径.md`。城市表 abgroup 过时要弃用；小时达表 abgroup 实际是仓/店标记但注释写"是否一体化城市"。小时达用 **0723 表**（abgroup = 仓库订单/小店/pro/其他，门店已拆 pro/小店；旧 v1_di 只到店铺订单粒度）。**任何维度字段先查 distinct 真实取值再用**。

### 坑4：飞书文档 block_replace 会改 block id
`docs +update --command block_replace` 替换段落后，**该 block 的 id 会变**。后续若还用旧 id 做 block_move_after/insert，会静默插错位置。
- **正解**：block_replace 之后**重新 fetch --detail with-ids** 拿新 id，再做后续移动/插入。或改用 str_replace（不改 id）做纯文本替换。

### 坑5：含 & 的内容要 markdown 模式
飞书 `str_replace`/`block_insert` 内容含 `&`（如"重庆&西安"）时，XML 模式会报 "Document engine internal error"，必须加 `--doc-format markdown`。media-insert 不接受 --api-version，且 --file 只吃 cwd 相对路径（绝对路径报 unsafe 静默丢图）。

### 坑6：不臆造关键输入
大促窗口/峰日、扣除系数、阈值这类关键事实，用户没给就**先问或从数据实测**，不套行业惯例当既定事实。采用近似口径必须显式标注"近似/预估、以实际为准"。

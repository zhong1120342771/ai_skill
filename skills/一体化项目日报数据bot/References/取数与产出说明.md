## 一、背景

线上线下一体化项目是当前产品侧的重点项目，需要建立一套数据监控机制，定位数据变化，判定不同业务动作进行后的数据变化情况以及是否存在异常点，助力核心指标增长。

**北极星指标**：
1. 同城订单量
2. 同城订单占比（同城订单量 / 总订单量）
3. 线下线索量
4. 线索转化总量
5. 同售订单量
6. 同售动销率（同售订单量 / 同售库存）
7. 小时达订单量

### 2.2 产出形式

报告标题：`【t-1 日（YYYY-MM-DD）一体化数据日报】`

#### 2.2.1 文字结论（消息开头）

报告开头给「结论」：把 7 项北极星指标分 4 段（每段一行 bullet），结论必须含具体数字。**同售一段内追加 pro店 / 小店 拆分**。

```
- 【同城订单&同城订单占比】同城订单 X（环比 ↑/↓Y%）；占比 X.X%（环比 ↑/↓Y%）
- 【线下线索量&线索量转化】线下线索 X（环比 ↑/↓Y%）；线索转化 X（环比 ↑/↓Y%）
- 【同售订单量&同售动销率】三层结构，子层在飞书消息里换行缩进展示：
    - 整体：同售订单 X（环比 ↑/↓Y%）；动销率 X.X%（环比 ↑/↓Y%）；
    - 小店&pro店：pro店 订单 X（环比 …）/动销率 …；小店 订单 X（环比 …）/动销率 …；
    - 城市拆解（小店同售）：一体化覆盖城市(小店) 订单 X（环比 …）/动销率 …；对照城市(重庆&西安) 订单 X（环比 …）/动销率 …；其他城市 订单 X（环比 …）/动销率 …
- 【小时达订单量】X（环比 ↑/↓Y%）
```

## 四、指标口径定义

| 指标 | 口径 | 数据来源 |
|---|---|---|
| 同城订单量 | `本地订单量`（if_bd=1）按 dt 汇总 | 01 线上订单 |
| 同城订单占比 | 同城订单量 / 总订单量 | 01 线上订单 |
| 线下线索量 | 02 线索表 中 `tag` = `线下线索` 类的 `xs_uv` 汇总 | 02 一体化线索 |
| 线索转化总量 | 02 线索表 中 `pay_uv` 汇总（不论线索类型） | 02 一体化线索 |
| 同售订单量 | 03 同售 `pay_pv` 汇总 | 03 同售动销 |
| 同售动销率 | 03 同售 `pay_pv` / `kc_ts` | 03 同售动销 |
| 小时达订单量 | 04 小时达 `jzf_pv` 汇总 | 04 小时达 |

> 「线下线索量」 vs 「线索转化总量」的具体 tag 取值如有歧义，以业务方说明为准；首跑时按 tag 全量做明细落表后，再由分析步骤拆分。

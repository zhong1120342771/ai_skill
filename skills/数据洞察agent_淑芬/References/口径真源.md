# 口径真源（single source of truth）

本文件是首页洞察流水线几条**跨 agent 复用口径**的权威副本。各 sub-agent 的 .md 里仍写有同口径的操作细节（隔离上下文需要就地可读）；**任何口径冲突，以本文件为准**。改口径的顺序：飞书文档先变 → 本文件同步 → 再改各 agent 就地文案。

> 为什么要这份文件：CTR/cap/ratio/收益折算这几条原本在 SKILL 全局约定 + 数据分析 + 洞察结论 + 机会计算器 + 质量检查 里逐字重复，没有指定权威副本，改一处容易漏改别处导致漂移。本文件指定权威副本，后续可逐步把各 agent 的就地文案收敛成"以口径真源为准"的引用。

## 一、CTR 唯一口径 = UV-CTR

- `uv_ctr = click_uv / exposure_uv`，业务读法「看到这个模块的人里有多少点了一下」。
- **PV-CTR 已彻底废弃**：schema/报告/图表都不出现 `pv_ctr` 字段或「PV-CTR」字样。
- `exposure_pv` / `click_pv` 仍照常采集上报（机会点 PV 体量、人均曝光 PV 等量级数要用），但**不计算 PV-CTR**。
- 机会点 gap 的「中位」分母 = **primary_page(G1001) 有曝光模块 UV-CTR 中位、剔除 capped venue_tab**，当日实算、不硬编。

## 二、场馆tab（section_id=106）曝光埋点 cap

- 场馆tab 是首页常驻 tab，曝光 UV 理论上 ≈ 首页曝光 UV；现网 zpmshow 对其漏报严重。
- **触发条件**：`venue_tab.exposure_uv / home_overall.exposure_uv < 0.90`（默认触发）。
- **替代**：`venue_tab.exposure_uv` 改记为 `home_overall.exposure_uv`；`uv_ctr` 用 `click_uv / home_overall.exposure_uv` 重算；`by_user_type` 各档分母换成对应分层的首页曝光 UV；`exposure_pv`/`click_pv` 保留原始值；新增 `exposure_capped` 记录原始值与触发原因。
- **报告显式标注**触发与原始数字；cap 后读数默认可信、据此下业务结论，**无需等 section106 埋点修复**（修复仅列附录工程待办）。
- capped venue_tab **不纳入**中位/对齐目标分母（会拉低中位、低估机会）。

## 三、样本 → 全量推广（ratio）

- `ratio = dau_full.uv / exploration.n_users`；`dau_full` 来自 `Scripts/dau_query.sql` 当日实跑，**绝不硬编 DAU**（大促/低谷浮动 20%+）。
- **只有 UV/PV/点击次数这类绝对量乘 ratio**（曝光/点击 UV·PV、点击次数、机会点覆盖人数、增量点击 UV）。
- **比例/统计量不乘 ratio**（UV-CTR/覆盖率/spread/χ²/jaccard——分子分母同比放大后数值不变）。
- 正文统一给全量推广量级，样本原始绝对量/N/抽样口径(1/339 哈希桶)/ratio 及来源放附录。健康 ratio ∈ [330,350]。

## 四、收益折算（单量 / GMV）

- 乘数只来自 `module_click_conv_aov`（Step1 保证产出，重试+近14日兜底），**GMV 折算取 page_id=G1001 的行**，**绝不自己拍**。
- `增量订单数(全量/日) = 增量点击 UV × pv_conv_rate_diff`（PV 转化率分子是订单数）。
- `增量 GMV(全量/日) = 增量订单数 × clicked_aov_per_order`（有点击组笔均客单价，元）。
- 提升型机会**强制**给单量/GMV，不再有「只给点击UV」降级；真无乘数（Step1 已 exit1 停在上游）则停下报错，不硬编。
- 单日相关含选择偏差，折算列**置信度上限 MEDIUM**，报告注明「需 A/B 校准」。
- `meta.source=fallback_from:X` 时报告标注「乘数取自 X 日，非当日」，置信度不再额外降。

## 五、多来源页面曝光埋点映射（搜索/feed/购物车/收藏/足迹）

用于「曝光→点击→商详→收银台→支付」跨页面来源链路分析。曝光/点击事件都在 `dw_log_lego_action_1d`；曝光 `pagetype='explosureGoods'`、点击 `pagetype='zpmclick'`；App 端。**页面识别（曝光/点击通用）就用下面这一套 actiontype+region：**

| 来源 | actiontype | region | 备注 |
|------|-----------|--------|------|
| 搜索 | `E1007` | `e` | 搜索结果页 |
| feed | `G1001` | `g` | 首页 feed 流；商品曝光 explosureGoods 层**不加 sectionId 限定**（会漏），首页区域限定 `sectionId IN ('108','110','109')` 只用于金刚/区域维度，不用于商品曝光取数 |
| 购物车 | `Q9753` | `q` | |
| 收藏 | `J2963` / `T2488` | `j` / `t` | 两个 actiontype+region 并列 |
| 足迹 | `V4961` | `v` | |

- **曝光**：`pagetype='explosureGoods'` + 上表 actiontype+region，商品 id 从 `datapool['goodsList']`（`&` 分隔）explode 取，token 去重。
- **点击**：`pagetype='zpmclick'` + **同一套 actiontype+region**，商品 id 取 `datapool['infoId']`（非空），token 去重。点击与曝光共用页面识别口径，不另找点击专属 actiontype。
- **商详/收银台/支付**走三张 dm 表（`dm_trade_visit_detail_1d`/`dm_trade_order_detail_1d`/`dm_trade_pay_detail_1d`），terminal IN ('15','16')；商详用 `first_from`、收银台/支付用 `ori_firstfrom` 做场景归因（救回收藏/足迹成单归因）。场景值：搜索=`search`/`recommend4Search`，feed=`homepage_rec`/`homepage_rec_personal`/`homepage_filter`/`homepage_rec_mix`，收藏=`getMyLoveInfosV3`/`getmyloveofflineinfoentrance`，足迹=`getfootprint`/`getfootprint_invalid`。
- **购物车**在 dm 表无 first_from 来源参数，其商详→收银台→支付走**时序链路**判定（购物车曝光时间戳后发生的商详/收银台/支付），不走场景归因。
- 2026-08-11 实测曝光 UV 量级参考：搜索 1,488,124 / feed 2,701,226 / 收藏 184,688 / 购物车 60,300 / 足迹 41,770。

## 一、这版是什么

把首页洞察的分析范围从「仅 G1001 首页」扩到四页：
- **G1001 首页 / G1002 奢品馆 / G1003 兴趣圈 / G1004 数码集**（均 region='g'）。

回答：四页各模块效率差异如何、量级贡献多大、是否值得常态纳入。与标准 G1001-only 版配套做 AB 对比。

**2026-07-13 起本版是日报常态**：用户已确认日常 cron 也跑四页（推翻早先「扩页面不进 cron」的判断）。历史数据侧观察是「扩页面净增触达可忽略（约 +0.03%）」，但四页对比信息（page×module 效率差异、分层三维）仍有结构参考价值，故并入主线常态产出；机会点排序仍**首页为主**，场馆页差异写正文/附录不硬排 P0。

> 注：结论开头不要写「扩页面几乎不带来净增触达/同一批人往深里逛」这类预设结论——用户明确说过不用反复强调，结论直接从当日效率信号切入。net_new 占比低就如实写一句，不夸大也不硬塞共识句。

## 三、口径

1. **CTR 唯一口径 = UV-CTR** = click_uv / exposure_uv，当天对 token 去重。PV-CTR 已废弃。
2. **绝对量 × ratio 推全量**（ratio = dau_full.uv / n_users）；比例/统计量不乘 ratio。ratio 落在 [330,350] 外要在报告标注偏保守/偏高。
3. **场馆tab（106）逐页 cap**：section106 曝光埋点漏报严重，`ratio_to_home = 场馆tab曝光UV / 该页整体曝光UV < 0.90` 触发 cap，`exposure_uv` 改记为该页整体曝光 UV。四页通常全触发。这条是**分母**修正，影响场馆tab自身模块级 CTR。
4. **★页面级 CTR 分子剔「离场型」点击（2026-07-13 修订）**：页面级 UV-CTR 分子剔除离场型点击，只留页内有效点击——
   - **场馆tab（106）**：G1002/G1003/G1004 剔（点了切别的场馆页=离场）；**G1001 首页不剔**（首页场馆tab视为首页内交互，历史口径）。
   - **底部导航栏（500，权威名"底部tab区域"）**：**四页统一剔**（点底tab切到App别的一级页=离场）。实际只有 G1001 有 section500（且是首页点击最大来源，约7000 UV/日），故仅影响首页——首页因此从92%降到70%。
   - **品类tab（300）/ 品牌墙（301）不剔**：馆内换品类、看品牌，不离页，是有效页内交互。
   - 分母（曝光 UV）不变。剔除按 UV 去重（只点了离场型、没点任何页内模块的用户从分子移除）。

### 口径 4 的作用边界（重要，别串味）

只作用于 **§1 页面级汇总 CTR**。其余分析层保持全口径点击：
- **§2 page×module 矩阵**：各模块（含场馆tab/底导航）仍是自己的 CTR，不受影响。
- **§3 增量贡献/净增触达**：用全口径点击（含所有离场型），衡量"多看到多少行为/多少人"，不是效率。**g1001 也要用原始 d3 算，别复用 page_overall 剔后的 click_uv，否则串味。**
- **§4 page×module×layer**：全口径，不动。

报告表头写清楚：`点击UV(全口径)` vs `点击UV(剔离场型)`。

### 口径 4 的代码落点

在 `analyze_4pages.py` 的 §1 page_overall 循环里：
```python
CTR_STRIP_VENUE_TAB_PAGES = {"G1002", "G1003", "G1004"}  # 剔场馆tab的页
BOTTOM_NAV_SECTION = "500"  # 底部导航,四页统一剔
d3["_sec"] = d3["sectionid"].map(norm_sec)   # 归一化去掉.0尾巴
for p in PAGES:
    c = d3[d3["page_id"] == p]
    c = c[c["_sec"] != BOTTOM_NAV_SECTION]        # (b) 底导航四页统一剔
    if p in CTR_STRIP_VENUE_TAB_PAGES:
        c = c[c["module"] != "场馆tab"]           # (a) 场馆tab仅G234剔
    clk_uv = c["token"].nunique()                 # 分母 e 不动
```
§3 的 g1001/per_page/incr_total 全部显式用**原始 d3**，不碰剔后值。

### 页面时长口径（补充）

时长分子=每用户当日该页 eventduration(秒)之和(仅正时长行);分母=该页有正时长记录的去重用户数。**注意 eventduration 大比例缺失,仅 24.5%~37.9% 访问用户有有效时长**,报告必须标注覆盖率、说明时长仅组间相对比较、不代表全体(见报告附录六)。无负时长,缺失全是 NaN。

## 七、注意点（踩过的坑）

- **模块名一律查权威维表,别信事件表 section_name_zh**（脏名会把品牌墙认成"预估回收价问号"、场馆tab认成"已废弃"）。见口径节维表查法。
- **106场馆tab / 300品类tab / 500底部导航 三个位别混**：106切场馆(离场,G234剔分子)、300馆内换品类(页内,不剔)、500底部一级页导航(离场,四页剔分子,实际只首页有)。121是feed心智条不是品牌墙,品牌墙是301。
- **口径 3(cap)和口径 4(剔分子)是两件事**：cap 修分母(曝光漏报,针对场馆tab自身模块CTR),口径4修分子(离场型点击不算页面有效点击),别混。
- **§3 别被 §1 剔后值串味**：g1001 的 exp/clk 必须用原始 d3 重算,不能取 page_overall["G1001"] 里剔后的 click_uv。首次改这版就踩过——首页 §3 曝光从 264万错成 201万。
- ratio 偏低会让全量绝对量偏保守，报告要标注、只作量级感。
- 兴趣圈 G1003 样本极小（曝光 99 UV），分模块/分层 CTR 只作方向参考。场馆页分层后每格样本更小,§4 三维热力慎读。
- **页面时长大比例缺失**：62%~76% 访问用户无有效 eventduration,时长仅组间相对比较,报告必须标覆盖率。

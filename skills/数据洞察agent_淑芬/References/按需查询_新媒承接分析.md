> 首次固化：2026-07-28，来源于董亚坤新媒承接分析需求（机会洞察联调群 oc_f9d6d274）。
> 这是**独立于主流水线的按需查询场景**，不进「代码生成→分析→质检→结论→机会计算器」五步编排；

## 一、需求

把三个**业务侧重点运营人群名单**，对齐**平台侧当日首次打上的意向标签**，看每个名单的人：
1. 有多大比例被平台打上了强/极强意向（匹配率）；
2. 打上意向的人，意向落到哪个业务（电子 / 兴趣 / 二奢）——即**意向流向**。

还要看**实验组 vs 大盘**的对照：同一套业务名单，平台侧只保留实验分组（period=true AND abValue=1）时，匹配率和流向结构有没有偏差。

分**整体版（不分端，APP+小程序全量）**和**仅 APP 端版**两套，各写一个飞书文档。

## 二、三条业务名单的圈选口径（业务侧重点运营人群）

三个名单都取单日 `dt`（默认取数日，样例用 2026-07-27），token 为用户唯一标识。

### 名单1 · 消费电子
平台标签事件直接圈：
```sql
action='queryRealTimeOneNewMediaUserTag' AND region='q'
  AND datapool['success']='true'
  AND datapool['businesslinetagname']='消费电子'
```
- 表：`hdp_zhuanzhuan_dw_global.dw_log_server_action_1d`
- region='q' 是 action 首字母小写（queryRealTime… → q）。
- **仅 APP 端版**：再 `INNER JOIN` 当日 APP 端活跃全集（`app_token` CTE，见下），剔掉纯小程序用户。整体版不 join。

### 名单2 · 二奢（B2C 二奢投放媒体触达的当日新媒活跃人群）
**不是** `businesslinetagname='二奢'` 标签，而是**投放触达 cohort**——B2C 二奢投放媒体当天触达、且当日在端上新媒活跃的人。四段 CTE：

1. `token_base`（整体版）/ `app_token`（APP 版）：当日端上活跃 token 全集，UNION 三张明细表去重：
   - `dm_oper_key_user_detail_inc_1d`（terminal 中文名 `转转APP`/`转转小程序`）
   - `dm_trade_exposure_info_detail_inc_1d`（terminal 数字码 15/16/20/103）
   - `dm_trade_visit_detail_1d`（同上）
   - 整体版 terminal 收 `转转APP`+`转转小程序` / `15,16,20,103`；APP 版只收 `转转APP` / `15,16,20`（去掉小程序 103）。
2. `b2c_lux_media`：B2C 二奢投放媒体 id 集
   - 表 `hdp_ubu_zhuanzhuan_view_global.ads_qsj_video_b2c_tag_full_1h_view`
   - `business_tag='b2c' AND multi_category_label IN (1,24,25,26,27,28,36,37)`（二奢品类标签集）
3. `b2c_today_new_media`：当天被这些媒体触达、且触达当天的人
   - 表 `dm_market_qsj_media_token_dtl_inc_1d` JOIN 上面媒体集 JOIN `t_zhuanzhuan_dau`
   - `plat_id IN (25,26)`；`from_unixtime(visit_ts,'yyyy-MM-dd') = dt`（触达日=当天）
4. `ershe_cohort`：`token_base`（或 `app_token`）INNER JOIN `b2c_today_new_media` → 最终二奢名单

> 二奢名单**整体版和 APP 版几乎一致**（180,727），因为这批投放触达人群本就基本在 APP。

### 名单3 · 兴趣（C2C 寄卖新媒体新归因弹窗）
业务侧兴趣重点评定，channelMark 回调事件圈：
```sql
action='channelMark' AND region='c'
  AND datapool['type']='callback'
  AND datapool['sortname']='C2C寄卖新媒体新归因弹窗'
```
- 表：`hdp_zhuanzhuan_dw_global.dw_log_server_action_1d`，region='c'。
- **仅 APP 端版**：再加 `terminal IN ('15','16','20')`（terminal 是 STRING，用字符串匹配）。
- **样本极小**：当日仅 33 个 token，流向结论不具代表性，只列出供参考、不下判断。兴趣用**单日**口径（钟梦婷 2026-07-28 确认）。

## 三、平台侧意向：强/极强意向的业务归属判定

**事件**：`newMediaInterestScore`（region='n'），平台给用户打意向分的事件。**实测只在 APP 端触发**（terminal 仅 15/16），所以平台侧分端前后一致，APP-vs-整体差异集中在消费电子名单剔除纯小程序用户。

**首次标签口径**：每个 token 当日按 `timestamp` 升序取**第一条** `newMediaInterestScore` 记录（`ROW_NUMBER() OVER (PARTITION BY token ORDER BY timestamp ASC)`，rn=1）。事件 reportTime 为空，用秒级 `timestamp` 排序。

**业务粒度直接读 guan 字段**（不走 cate_id 映射）：
```sql
get_json_object(datapool['strongintent'],  '$.guan') AS strong_guan   -- 强意向的业务归属
get_json_object(datapool['extremeintent'], '$.guan') AS extreme_guan  -- 极强意向的业务归属
```
- `guan` 取值当日只有三类：**电子 / 兴趣 / 二奢**。
- **强意向（strongintent）与极强意向（extremeintent）互斥**：单条首次记录里两者不同时有值，合并计入该用户意向流向。
- `matched_intent`（匹配上意向）= 首条记录 `strong_guan` 或 `extreme_guan` 有值。**只保留 matched_intent**，不再算「进意向池 in_platform_pool」那个口径（钟梦婷 2026-07-28 明确砍掉）。

> 流向分母 = 各名单的 matched_intent 用户数；首标签口径下每人当天只落一个 guan，是互斥拆分，各业务占比合计 100%。

## 四、实验组区分

实验组 = 平台打分记录里 `datapool['period']='true' AND datapool['abvalue']='1'` 的基础候选人群（董亚坤 newMediaInterestScore AB 口径，abvalue=1 实验组 / 0 对照组）。

- 实验组版 SQL 只在 `plat` CTE 的 `newMediaInterestScore` 过滤里**加这一条**，业务名单三个 CTE 完全不变（分母仍是全量业务名单）。
- 实验组匹配率约为大盘的 1/5，对应实验分组当天覆盖约 18% 的打分流量——**分母是全量名单、只有命中分组的人有标签**，所以这是分母口径造成的，不是承接质量下降。
- 消费电子、二奢两版流向结构高度一致 → 实验分组未引入承接结构偏差。

## 七、口径与局限

1. **单日快照**：仅取数日一天，非趋势。
2. **端判定**：`terminal IN ('转转APP','转转小程序')` 或数字码 `15,16,20,103`；**15安卓/16iOS/20 = APP 端**，103 = 转主小程序。
3. **二奢是投放触达 cohort**，非业务自打标签，性质为「B2C 二奢投放媒体触达」。
4. **兴趣样本极小**（33 token），流向不具代表性，仅供参考。
5. **首标签口径**：每 token 当日 timestamp 升序第一条 newMediaInterestScore。
6. **业务粒度来自 guan**，不走 cate_id 映射，当日 guan 取值只有电子/兴趣/二奢三类。
7. **强/极强互斥**，合并计入意向流向。
8. **实验组** = period=true AND abValue=1，董亚坤指定的基础候选人群口径。
9. **只保留 matched_intent**，「进意向池」口径已砍掉。

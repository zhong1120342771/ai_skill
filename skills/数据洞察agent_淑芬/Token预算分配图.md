# 数据洞察agent_淑芬 Token 预算分配图

对淑芬这条流水线的每条指令消息做了一次 token 估算。先说最关键的一点：淑芬不是「一个上下文吃掉一份预算」，而是「1 个编排器主上下文 + 6 个相互隔离的子 agent 上下文」。所以预算是分散的，全目录朴素合计约 9.6 万 token，但任一时刻真正的约束只是当前那一个上下文，不能把 6 份定义加在一起看。

估算口径：中文字符按 0.9 token/char、ASCII（英文/代码/符号）按 0.28 token/char 分档换算，属于量级估计，不是精确计费。

## 三层结构

```
全局固定层（每个上下文都背，卸不掉）
CLAUDE.md 1847 + MEMORY.md 1109 ≈ 2,956 tok
        │（叠加进下面每一个上下文）
        ├──────────────┬─────────────────────────┐
        ▼              ▼                          ▼
编排器主上下文        6 个子 agent（各自独立上下文，互不叠加）
SKILL.md ≈7,835     代码生成 5026 / app体验 5360 / 数据分析 9609
（常驻主线程）        质检 4975 / 洞察结论 12512 / 机会计算器 11953
+ 6 次调度状态(极小)
```

## 固定开销 / 动态开销 / 可压缩

| 类别 | 内容 | 估算 token | 说明 |
|---|---|---|---|
| 固定 | CLAUDE.md + MEMORY.md | 2,956 | 每个上下文都背，除非精简全局配置 |
| 固定 | SKILL.md 编排器 | 7,835 | 常驻主线程，是编排器的宪法 |
| 固定 | 6 个子 agent 定义 | 49,435 合计 | 分 6 个隔离上下文，单次只加载 1 份 |
| 动态 | 上游落盘产物摘要(json/md) | 每步 2~15k | 随当天模块数、假设数、机会点数浮动 |
| 动态 | CSV 原始数据 | 约 0 入上下文 | 70MB 曝光表由 pandas 处理，只回流摘要 |
| 可压缩 | SKILL.md 偏胖 | 可省 ~2,500 | 红线速查、路径大小写告警有重复 |
| 可压缩 | 洞察结论生成、机会计算器 | 各可省 ~3,000 | 两份定义把 References 内容抄了一遍 |
| 可压缩 | References 被多步重复读 | 视调用 | output-schemas 6,598，多个机器产物步骤都读 |

## 单上下文实际峰值

真正决定会不会爆预算的，是当前那一个子 agent 的上下文，不是全目录合计。

- Step5 机会计算器峰值 ≈ 全局 2,956 + 定义 11,953 + Step4 报告 ~6,000 + exploration/hypotheses/quality 摘要 ~5,000 + dau_full/conv_aov 小量 ≈ **26,000 tok（全链最贵）**
- Step2/Step3 中段 ≈ 全局 2,956 + 定义 + CSV 摘要 ≈ 12,000~18,000 tok
- 编排器主线程 ≈ 全局 2,956 + SKILL 7,835 + 调度状态 ≈ 11,000 tok（很稳）

## 三个可压缩抓手（2026-07-31 已落地一轮）

1. **两份子 agent 收敛口径（已做，保守）**：`洞察结论生成.md`、`机会计算器.md`、SKILL.md 正文里把 CTR/cap/ratio/收益折算的口径定义逐字重复。已在三处顶部加 `References/口径真源.md` 权威指针，压掉纯重复论证（如反复讲"PV-CTR 为什么废弃"）。**但保留了全部就地操作细节**（公式变量映射、报告标注要求、字段清单、飞书流程）——这些是隔离上下文的刻意设计，删了子 agent 就没法就地执行。所以实际省的比早先估的 6,000 少（多数是必留细节），量级约 2,000~3,000。
2. **SKILL.md 收敛（已做）**：正文「全局约定」的 CTR/cap/全量推广三条压成"关键约束 + 指向口径真源"的短句；末尾 ❌/✅ 速查表**保留不动**（那是编排器/维护者一眼看全红线的好设计，不是冗余）。
3. **死代码清理（已做，收益最直观）**：`Scripts/` 原有 9 个 `run_step1_<日期>.py` + exploration/repoll/resilient/build_md 快照共 14 个文件（3,397 行 / 200K），逐字雷同只差 DT 常量、无任何引用。已收敛成参数化 `run_step1.py --dt`，并在 `代码生成.md` 加固化脚本指引从根上止住每日新建快照。这些不占运行时 token，但清掉后 `Scripts/` 只剩 7 个固化入口，子 agent glob 时不再有同名噪声、迁移包不再虚高。
4. **不该动的别动**：CSV 大表走 pandas 不进上下文；`Scripts/` Python 是执行体不进 prompt；`_bundled_deps/` 是迁移物料任何子 agent 都不读——这三块对运行时 token 贡献接近零，不是压缩目标。

## 结论

淑芬的架构本身就省 token：靠子 agent 隔离把定义拆成多份错峰加载，靠「CSV 走 pandas 不走上下文」避开几百 MB 数据。2026-07-31 这轮优化：口径去重（顶部加权威指针、压纯论证、留操作细节）+ SKILL 正文收敛 + 清 14 个死代码脚本。运行时 token 省约 2,000~3,000（保守，因就地细节刻意保留）；更大的收益在**可维护性**——口径改一处传导清晰、Scripts/ 无同名快照噪声。

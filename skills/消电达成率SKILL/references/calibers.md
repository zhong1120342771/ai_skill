# 口径字典（消电达成率评估）

这些口径是团队既定的，评估时直接沿用，**不要用行业惯例另编一套**。缺哪个口径就问用户或从底表实测，别默认生成。

## 达成率主口径

| 概念 | 定义 | 说明 |
|------|------|------|
| 月比率 | 月内先把分子、分母各自加总，再相除 | 不是先算日比率再平均。跨月/跨季同理：窗口内先加总再除 |
| 实际提升 | (末月比率 − 首月比率) / 首月比率 | 相对提升，不是绝对差（pct 差）。H1 默认首月=1月、末月=6月 |
| 目标提升 target | 配置里给的目标相对提升，如 +15% → 0.15 | |
| 达标 | 实际提升 ≥ 目标提升 | |
| 目标线（图上虚线） | 首月值 ×(1+target) | 末月点在虚线上方=达标 |

## 各指标分子/分母

| 指标 | num/den | 备注 |
|------|---------|------|
| 曝光渗透率 | exp_uv / uv_all | uv_all = 消电大盘 UV（当分母的口径要和目标定义一致） |
| 商详到达率 | detail_uv / exp_uv | = 馆页面曝光点击率的口径 |
| 商详渗透率 | detail_uv / uv_all | 注意与"商详到达率"分母不同 |
| 下单率 | order_uv / detail_uv | |
| 支付效率 | pay_pv / order_uv | 倍数，不是百分比（is_percent=false） |
| 提袋率 | pay_pv / exp_uv | = 曝光渗透率 × 商详到达率 × 下单率 × 支付效率 |
| 商详转化率 | pay_pv / detail_uv | = 下单率 × 支付效率 |
| 人均曝光PV | exp_pv / exp_uv | 倍数，非百分比 |

## 漏斗链路（归因时把提袋率沿这条链拆）

```
曝光渗透率(exp_uv/uv_all) → 商详到达率(detail_uv/exp_uv) → 下单率(order_uv/detail_uv) → 支付效率(pay_pv/order_uv)
提袋率 = pay_pv/exp_uv = 上面四环连乘
```
拆开后看是哪一环把整体拖平：前端（曝光渗透）掉，还是后端（下单/支付）掉。这是本轮归因的核心结论方式。

## 底表 vs 明细 CSV 的分母陷阱（重要）

- **明细 CSV**：分母 `uv_all` = 消电大盘 UV。
- **核心底表**（`hdp_zhuanzhuan_tmp_global.tmp_dws_zz_core_dataagent_zmt_v2_di`）：`matched_dau_uv` = 该维度匹配到的全站 DAU（业务行是全站 DAU）。

两者口径不同，**不可混算渗透率**。跨两个数据源对比时，只能横比"曝光UV 增长率"（与分母无关），涉及渗透率必须同源。任何跨源对比在产出里加脚注说明。

## 维度标签（tag_01 / wd 取值）

- 单维度：`tag_01='拆分品类'`（wd 如 `1-手机`/`2_5类目`/`4-平板`…）、`tag_01='拆分场景'`（wd 如 `馆`/`搜索`/`首页金刚位`）、`tag_01='整体'`（wd=`整体`）。
- 交叉维度：`tag_01='交叉-品类_场景'` / `交叉-品类_用户来源` / `交叉-品类_新媒vs自然` / `交叉-用户来源_场景` / `交叉-品类_新老用户` 等，wd 用下划线拼两个维度值。
- 底表业务行：`tag_01='单维度-拆分品类'`，wd=`业务_消费电子`/`业务_兴趣`/`业务_二奢`；智能手表/耳机在明细里无单独维度，走底表 `wd LIKE '%智能手表%' / '%耳机%'` 补。
- 品类归类另见全局记忆 `zhuanzhuan-category-taxonomy-facts`（五品类=乐器/台球杆/骑行/潮玩/球拍；包袋腕表鞋服饰品属二奢，剔除）。

## 数据可靠性检查（踩过的坑）

- 某月曝光UV 腰斩但 detail/order/pay 没跌 = 埋点回刷不全，不是真跌。该月剔除或改用相邻完整月。上轮 6 月三业务曝光即此情况，业务对比只取 1→5 月。
- 场景 `section_id=106`（场馆tab）曝光漏报严重，曝光UV/首页UV<90% 触发 cap（见记忆 `shufen-venue-tab-exposure-cap`）。
- 7 月为不完整月，H1 评估默认排除。

# Aggregation Report

本文档用于 `user-chance-lab` 基于多轮 `user-chance` 报告生成聚合体验结论、机会点报告或竞品对比报告。

## 聚合原则

聚合不是把单轮报告拼起来，而是判断哪些体验问题跨角色、跨任务、跨路径重复出现，哪些只是单次线索，哪些受工具或样本限制影响。

优先纳入 `lab_run_manifest.md` 标记为 `valid` 的样本。`partial_valid` 只能作为方向信号或样本限制，不得和 `valid` 同权重。被剔除样本只能作为工具风险、样本限制或待复测记录。

样本有效性和结论强度必须分开处理。一轮是 `valid`，只代表这轮整体可用于聚合；某个具体结论仍可能因为依赖 XML 屏外、推断或工具噪声而需要降权。

## 读取顺序

1. 读取 `lab_run_manifest.md`，确认纳入样本。
2. 读取有效样本的 `report.md`。
3. 提取每轮的角色、任务、用户状态、体验问题、机会点、证据索引和样本限制。
4. 区分 `valid`、`partial_valid` 和 `invalid`，先确定样本权重。
5. 读取每轮 caveat，标注关键证据来自截图可见、XML 可见、XML 屏外、推断还是工具噪声。
6. 归并同类问题。
7. 判断问题证据强度和影响范围。
8. 输出聚合报告。

## 证据来源等级

| 来源 | 判断 | 聚合要求 |
|---|---|---|
| 截图可见 | 用户路径上真实截图可见 | 可写成用户看到，可支撑高强度结论 |
| XML 可见 | UI XML 中存在且 bounds 在屏幕内 | 可辅助判断；若缺截图支撑，最高一般为中 |
| XML 屏外 | UI XML 中存在但屏幕不可见、隐藏或疑似残留 | 只能写成页面可能存在，不能写成用户已看到 |
| Agent 推断 | 来自角色、上下文或经验判断 | 只能写成假设 / 方向信号 |
| 工具噪声 | XML 滞后、坐标换算、误点、历史页面污染、模拟器摩擦 | 写入样本限制，不进入产品问题池 |

## 证据强度

| 强度 | 标准 |
|---|---|
| 高 | 多轮出现，且跨角色 / 任务仍成立，有明确证据 |
| 中 | 2 轮左右出现，或单轮证据强但覆盖有限 |
| 低 | 单轮线索、Agent 推断或受样本限制 |
| 工具限制 | 由 MCP / ADB / 模拟器 / 输入问题导致，不写成产品问题 |

强度上限：

| 证据情况 | 最高强度 |
|---|---|
| 多轮截图可见，且角色/路径差异下仍成立 | 高 |
| 截图可见但样本少，或 XML 可见辅助为主 | 中 |
| 主要依赖 XML 屏外、Agent 推断或 partial_valid 样本 | 低 / 方向信号 |
| 主要来自工具噪声 | 工具限制 |

不要把 `xml_offscreen` 写成“用户已看到”，不要把工具误点、历史残留、坐标换算或 XML 滞后写成产品体验问题。

## 机会点分级

| 级别 | 判断 |
|---|---|
| P0 | 阻断目标完成或导致重大错误决策 |
| P1 | 明显降低信任、效率或决策质量，高频或高影响 |
| P2 | 局部摩擦、可优化，但不阻断核心目标 |
| P3 | 轻量文案、提示、排序或信息呈现优化 |

## 聚合报告必须回答

| 模块 | 内容 |
|---|---|
| 实验概览 | 跑了几轮、有效几轮、剔除几轮、覆盖哪些角色 / 任务 |
| 总体结论 | 这批用户完成目标的整体体验如何 |
| 高频体验问题 | 跨轮重复出现的问题，按影响排序 |
| 关键机会点 | 产品可以怎么改，为什么值得改 |
| 角色差异洞察 | 不同角色在哪些环节出现差异 |
| 任务 / 路径差异 | 多任务或指定路径时，各路径表现差异 |
| 证据索引 | 每个结论对应哪些轮次和报告位置 |
| 样本权重说明 | 哪些样本完整有效，哪些只是方向信号，为什么 |
| 证据 caveat | 哪些结论依赖截图可见，哪些包含 XML/屏外/推断限制 |
| 样本限制 | 工具、起点、账号、样本量、路径覆盖限制 |
| 下一步建议 | 是否复跑、扩样、做人研、做 AB 或进入需求池 |

## 竞品对比

如果是多 App 竞品对比，结论要按同一用户目标比较，不要只比较页面功能。

对比维度：

- 目标进入是否自然
- 候选发现效率
- 价格 / 风险 / 保障信息是否可理解
- 决策证据是否闭合
- 用户信任建立速度
- 放弃或转向原因
- 哪个 App 更容易让用户形成可解释判断

输出时区分：

| 类型 | 说明 |
|---|---|
| 体验优势 | 用户更容易理解、信任或完成决策 |
| 产品机会 | 本 App 可借鉴或需要补齐的能力 |
| 场景差异 | 由于平台定位、商品供给或用户任务不同导致，不直接判断优劣 |

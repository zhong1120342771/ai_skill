# Experiment Design

本文档用于 `user-chance-lab` 设计批量实验计划、自动分配角色和生成 `user-chance` 单轮任务卡。它不负责真实 App 操作。

## 设计目标

批量实验不是随机多跑几次，也不是人为覆盖入口。它要用有限样本覆盖不同真实用户的决策方式，让多轮结果能暴露体验问题和机会点。

```text
目标约束槽位解析
-> 用户差异组合
-> 多轮角色 / 任务设计
-> user-chance 自然语言任务卡
```

## 目标约束槽位

先把少爷给定目标拆成槽位。每个槽位都要判断是否存在、明确程度、约束强度、来源和可变空间。

| 槽位 | 说明 | 示例 |
|---|---|---|
| 目标对象 | 用户要找什么 | 手机、iPhone、iPhone17、ThinkPad |
| 使用场景 | 买来干什么 | 备用机、送礼、主力机、办公、急用 |
| 商品参数 | 商品规格 | 容量、颜色、尺码、版本、配置、屏幕尺寸 |
| 商品状态 | 新旧和质量状态 | 成色、瑕疵、电池、维修、配件、是否拆修 |
| 风险保障 | 可信度和售后要求 | 质检、保修、平台验、退换、正品保障 |
| 价格价值 | 价格和性价比要求 | 预算上限、高性价比、券后价、低价原因 |
| 时效履约 | 到手时间和交付方式 | 尽快、次日达、同城自提、包邮、发货时间 |
| 决策产出 | 用户最终要形成什么判断 | 找到一个、对比后选一个、判断是否值得买 |

槽位属性：

| 属性 | 取值 | 说明 |
|---|---|---|
| `presence` | present / absent / inferred | 是否存在该要求 |
| `specificity` | vague / range / precise / contextual / none | 明确到什么程度 |
| `firmness` | hard / strong_preference / preference / exploratory | 约束强度 |
| `source` | explicit_goal / persona_inference / category_norm / industry_risk / page_signal / lab_design | 来源 |
| `variability` | fixed / lightly_variable / discussable / not_set | 可变空间 |

示例：

| 用户说法 | 槽位 | 明确程度 | 约束强度 |
|---|---|---|---|
| 想买手机 | 目标对象 | vague | exploratory |
| 想买 iPhone17 | 目标对象 | precise | strong_preference |
| 要大容量 | 商品参数 | vague | preference |
| 要 256G 以上 | 商品参数 | range | strong_preference |
| 次日达 | 时效履约 | precise | hard |
| 尽快送达 | 时效履约 | vague | preference |

不要把模糊需求随便改成精确需求，也不要把精确需求随便放宽。Agent 可以在执行中解释模糊需求，但必须说明解释依据。

## App / 行业语境

商品状态和风险保障要随 App 与行业变化。

| 场景 | 重点 |
|---|---|
| 转转 / 二手交易 | 成色、瑕疵、维修、电池、配件、质检、保修、低价原因、平台可信度 |
| 新品电商 | 正品、版本、库存、官方保修、发货时效、优惠规则 |
| 本地生活 / 服务 | 距离、预约时间、服务范围、评价、履约确定性 |
| 租赁 / 回收 | 押金、损耗规则、估价透明度、履约风险 |

默认 App 是转转时，二手交易的风险、状态和保障通常是高优先级语境，即使少爷没有逐字写出。

## 用户差异维度

角色生成只使用能真正驱动行为的用户差异。

| 维度 | 分层 | 说明 |
|---|---|---|
| 价格 / 风险权重 | 价格高风险中、价格中风险高、价格高风险高、价格中风险中 | 两者并存，只调整权重 |
| 平台熟悉度 | 首次、普通、熟悉 | 是否理解平台规则、券、质检、保障、活动 |
| 品类熟悉度 | 小白、基础了解、懂行 | 是否理解参数、成色、风险、术语 |
| 初始耐心 | 低、中、高 | 愿意承担的探索、比较和核验成本 |

不作为前置角色维度：

| 项 | 处理 |
|---|---|
| 入口倾向 | 由角色、目标和当前页面自然推导 |
| 决策弹性 | 由目标槽位、约束强度和可变空间推导 |
| 用户关注度 | 由熟悉度、步骤、页面密度、摩擦和候选吸引力动态变化 |
| 浏览深度 | 由关注点缺口、候选成熟度、耐心和信任变化决定 |

## 默认 5 轮生成逻辑

默认 5 轮不是固定人设，而是覆盖不同决策方式。生成时按任务适配，不要机械套模板。

建议覆盖：

| 样本 | 目标 |
|---|---|
| 价格主导但不忽视风险 | 看低价、优惠、同款对比是否能支撑判断 |
| 风险主导但仍看价值 | 看质检、保障、成色、瑕疵、售后是否能建立信任 |
| 平台新手 | 看平台信息、规则、入口和弹窗是否容易理解 |
| 品类差异样本 | 小白或懂行用户如何理解参数、状态和低价原因 |
| 耐心差异样本 | 看信息成本、路径摩擦和候选成熟度如何影响放弃 / 暂缓 |

如果少爷指定多任务，优先让 5 轮覆盖“角色差异 + 任务差异”的组合；如果少爷指定单任务，5 轮主要覆盖角色差异。

## 目标变更边界

不要替用户猜隐藏需求。用户给定目标就是目标。

允许讨论升级、降级或横向替代的前提：

1. 初始目标流程的信息成熟度已经足够，能判断原目标是否成立或存在明显更优解。
2. 变更只发生在可变目标对象或参数上，例如机型、容量、成色、保障档、价格档。
3. 不能改变固定使用场景、硬预算、安全边界、报告目的等不可变约束。
4. 最终报告必须说明为什么发生变更，以及它代表产品帮助发现更优解，还是原目标承接不足。

## 单轮任务卡生成

每轮任务卡要翻译成人话，保证 `user-chance` 能独立执行。

模板：

```text
第 N 轮 / 尝试 M：
App：转转
角色：……
任务目标：……
禁止边界：……
本轮行为倾向：……
判断标准：……
目标可变空间：……
报告要求：本轮结果后续进入 user-chance-lab 聚合，请输出样本有效性、用户状态、关键体验问题、机会点和证据索引。
```

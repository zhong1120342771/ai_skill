## 二、来源识别（曝光 & 点击共用 actiontype + region）

```sql
CASE
  WHEN actiontype='E1007' AND region='e' THEN '搜索'
  WHEN actiontype='G1001' AND region='g' THEN 'feed'
  WHEN actiontype='Q9753' AND region='q' THEN '购物车'
  WHEN actiontype IN ('J2963','T2488') AND region IN ('j','t') THEN '收藏'
  WHEN actiontype='V4961' AND region='v' THEN '足迹'
END
```

- 收藏有两个 actiontype（`J2963` 在线 / `T2488` 离线），对应两个 region（`j`/`t`），要一起收。
- 曝光额外要求 `pagetype='explosureGoods'`；点击要求 `pagetype='zpmclick'`。
- 点击侧简化版可只按 region 打标（`e/g/q/j,t/v`），因为 zpmclick 的 region 已足够区分来源。

## 三、infoId 解析

### 曝光：goodsList explode

`datapool['goodsList']` 是 `&` 分隔的多商品串，展开取单个 gid：

```sql
FROM dw_log_lego_action_1d
LATERAL VIEW explode(split(datapool['goodsList'],'&')) g AS gid
WHERE dt='${DT}' AND pagetype='explosureGoods'
  AND <来源 actiontype+region 条件>
  AND token IS NOT NULL AND token<>'' AND gid IS NOT NULL AND gid<>''
-- info_id = CAST(gid AS BIGINT)
```

### 点击：datapool['infoId']

```sql
FROM dw_log_lego_action_1d
WHERE dt='${DT}' AND pagetype='zpmclick' AND region IN ('e','g','q','j','t','v')
  AND datapool['infoId'] IS NOT NULL AND datapool['infoId']<>''
  AND token IS NOT NULL AND token<>''
-- 取出 iid = datapool['infoId']，过滤 iid RLIKE '^[0-9]+$'，再 CAST AS BIGINT
```

去重粒度都是 `(src, token, info_id)`；最终 UV = `COUNT(DISTINCT token)`。

## 四、业务归类（info_id → 4 业务）

```sql
biz AS (
  SELECT info_id,
    CASE WHEN cus_business_bu IN ('消费电子') THEN '消费电子'
         WHEN cus_business_bu IN ('二奢') AND business_line_id IN (915051,915061) THEN '二奢'
         WHEN cus_business_bu IN ('二奢') THEN '兴趣'
         WHEN cus_business_bu IN ('长尾N') THEN '兴趣'
         ELSE '其他' END AS cate
  FROM hdp_zhuanzhuan_dw_global.dw_mysql_info_full_1d
  WHERE dt='${DT}'
    AND cus_business_extend['is_cp_flag']='0' AND cus_business_extend['is_live_flag']='0'
    AND (cus_business_bu IN ('消费电子','长尾N','二奢')
         OR (cus_business_belong IN ('B2C') AND cate_second_id IN ('120'))
         OR (cate_id='2120006' AND cus_business_belong IN ('B2C')))
  GROUP BY info_id, 2
)
```

埋点/交易表的 `info_id` `LEFT JOIN biz`，`COALESCE(b.cate,'其他')` —— 维表未命中的商品归「其他」。

## 五、场景归因（商详/收银台/支付）

三表 union，商详取 `first_from`，收银台/支付取 `ori_firstfrom`：

```sql
v AS (
  SELECT '1商详' AS step, token, info_id, first_from AS fromcol
  FROM dm_trade_visit_detail_1d
  WHERE dt='${DT}' AND terminal IN ('15','16') AND token<>'' AND info_id IS NOT NULL
  UNION ALL
  SELECT '2收银台', token, info_id, ori_firstfrom
  FROM dm_trade_order_detail_1d WHERE dt='${DT}' AND terminal IN ('15','16') ...
  UNION ALL
  SELECT '3支付', token, info_id, ori_firstfrom
  FROM dm_trade_pay_detail_1d WHERE dt='${DT}' AND terminal IN ('15','16') ...
)
```

fromcol → 来源：
```
搜索:  search, recommend4Search
feed:  homepage_rec, homepage_rec_personal, homepage_filter, homepage_rec_mix
收藏:  getMyLoveInfosV3, getmyloveofflineinfoentrance
足迹:  getfootprint, getfootprint_invalid
其他来源: 其余（分析中过滤掉，不进 4 来源）
```

**红线**：收藏/足迹的收银台/支付归因必须用 `ori_firstfrom`。用 `first_from` 会导致下游成单归因归零（历史踩坑，见 memory `zhuanzhuan-collection-footprint-ori-firstfrom`）。

## 六、购物车时序链路

购物车在交易 dm 表无 first_from，改时序：购物车曝光时间戳为锚，其后发生的 visit/order/pay 才算命中。粒度 `(token, info_id)`，判定后聚合到品类。完整 SQL 见 `scripts/cart_sequential_chain.sql`。

关键片段：
```sql
chain AS (
  SELECT c.token, c.info_id,
    MAX(CASE WHEN vv.view_ts>=c.cart_ts THEN 1 ELSE 0 END) AS rv,
    MAX(CASE WHEN oo.ord_ts >=c.cart_ts THEN 1 ELSE 0 END) AS rc,
    MAX(CASE WHEN pp.pay_ts >=c.cart_ts THEN 1 ELSE 0 END) AS rp
  FROM cart c
  LEFT JOIN vv ON c.token=vv.token AND c.info_id=vv.info_id
  LEFT JOIN oo ON c.token=oo.token AND c.info_id=oo.info_id
  LEFT JOIN pp ON c.token=pp.token AND c.info_id=pp.info_id
  GROUP BY c.token, c.info_id
)
```
`cart_ts = MIN(timestamp)/1000`（毫秒转秒），dm 三表各取 `MAX(timestamp)`。

## 七、数据现象备注

- 足迹「点击→商详」>100%：点击(埋点 zpmclick) 与商详(dm first_from 场景归因) 两套源交叉，非错误。
- feed「其他」点击 UV=0：埋点缺失切片，不补造。
- 转化率分母为 0 时输出 `—`，不写 0/NaN。

# 结论生成（Step 6）

把异动分析翻译成业务能懂的结论 + 图表，建飞书文档并 P2P 推送。**只在质检 `passed=true` 后执行。**

## 基础与定位

流水线第 6 步、唯一对外出口。职责边界：把上游"是否异常→哪个环节→哪个特征维度"的分析事实，翻译成经营分析师视角的业务结论、出图、建飞书文档并 P2P 推送给钟梦婷。产物直接给业务看，两条底线不能破：**比率必带绝对量**、**口径表述不能错**。对外成段文字交付前过 humanizer 去 AI 味（只改措辞，不动数字/口径/结论）。

### Step A2：分业务异常判定（核心结论必答，写报告前必跑）
出报告前**必须**先跑分业务诊断，拿到消费电子/二奢/兴趣三业务的今日异常判定——这是仅次于大盘北极星的第一优先级结论，不可省略：
```bash
python ~/.claude/skills/转转核心指标异动监控bot/scripts/business_diagnose.py \
  --input ~/.claude/analysis_reports/tidy_${dt}.csv --analyze-dt ${dt} \
  --out ~/.claude/analysis_reports/biz_diagnose_${dt}.csv
```
读产物 `biz_diagnose_${dt}.csv` 的业务级行（`level=业务`）三列：`biz_anomaly`（True/False/None）、`biz_anomaly_verdict`（如"异常↓（单量 -15.1% 越 ±15%）"）、`biz_anomaly_reason`（北极星/单量环比+拖累环节）。若 Step 4 已产出该 CSV 可直接复用，不必重跑。
> 判据：北极星 `dau_pay_rate` 或 单量 `pay_pv` 环比（上周同日优先、缺则 t-1）任一越 **±15%** 即判异常，方向北极星优先。**这三业务的判定必须逐个进"结论先行"和"分业务异常判定"块，逐个点名正常/异常，不能只报大盘。** 判"数据不足"如实标注。

### Step A3：分场景判定（流量分发 + 转化效率，改点3，写报告前必跑）
判各场景对**大盘**和**各业务**的两件事是否降低：流量分发（曝光UV + 曝光渗透率）、转化效率（提袋率＝商详到达率×商详转化率）。若某业务在某场景的流量或转化效率有问题，脚本自动细拆到该业务的**品类**定位。
```bash
python ~/.claude/skills/转转核心指标异动监控bot/scripts/scene_diagnose.py \
  --input ~/.claude/analysis_reports/tidy_${dt}.csv --analyze-dt ${dt} \
  --out ~/.claude/analysis_reports/scene_diagnose_${dt}.csv
```
读产物 `scene_diagnose_${dt}.csv`：`level`（大盘场景/业务场景/品类场景）、`scene_verdict`（`流量分发↓`/`转化效率↓`/`正常`）、`scene_reason`（曝光UV/曝光渗透率/提袋率环比明细）。报告「分场景判定」段先给大盘各场景结论，再点名走弱的业务×场景并给出细拆到的品类。
> **馆场景 2027-01-01 前暂停年同比（用户指定口径规则，2026-07-15，硬约束）**：馆场景（`main_scene=馆` 及下辖二/三级场景如「馆金刚位」）近一年归类口径/埋点有年度变化、去年同期不可比。**2027-01-01 之前，馆场景在 §三 表1/表2 与分场景判定里的「同比周/同比日」两段一律填「—（口径变化暂停同比）」，不呈现同比幅度、不当真实业务下滑播报**；馆场景的环比（t-1/上周同日）、曝光/转化现状照常给。仅限「馆」家族，其余场景年同比照常。详见 [../../references/日历与季节性.md](../../references/日历与季节性.md) §四·补2。
> **兴趣 / 二奢 低基数暂停年同比（用户指定口径规则，2026-07-20，硬约束）**：兴趣、二奢 两业务 2025 年转化率/单量基数低，同比易误报。**同比基准日 < 2026-01-01 时，兴趣/二奢 的转化率（北极星+漏斗各环节率）与单量的「同比周/同比日」两段一律填「—（25年低基数暂停同比）」，不呈现同比幅度、不当业务波动播报**；环比与现状照常给。`business_diagnose.py` 已把这两业务的同比列置空并标 `yoy_suppressed`。仅限含「兴趣」「二奢」的行，其余业务照常。分析日到 2026-12-31 后自动恢复。详见 [../../references/日历与季节性.md](../../references/日历与季节性.md) §四·补3。
> 依赖 tidy 含 `3维度交叉-端_业务/品类_场景` 族才能做业务×场景与品类下钻；缺该族时脚本会告警只出大盘×场景，报告如实标注「业务×场景待取数补该交叉族」。阈值默认 -15%（`--threshold` 可调），与大盘/分业务一致。

### Step B：写报告
按 `assets/report-template.md` 填 `final_report/核心指标异动_${dt}.md`。核心要求（经营分析师视角）：
- **章节顺序（v3-0711 改点2）**：一、结论先行 → **二、北极星现状（提到分业务/分场景之前）** → 三、异常判定总表（拆表1转化效率/表2流量两张大表）→ 四、漏斗链分解 → 五、特征维度 → 六、图表约定。**不要单列「数据局限」模块（v3-0711 已删）**；确有影响结论的关键缺口，一句话并进相关表注即可。
- **§三 拆两张表（v5-0711 改点1，硬约束）**：§三 用**两张表**覆盖大盘/分用户来源/分业务/分场景四层级——
  - **表1 转化效率**：`层级|对象|今日判定|转化效率(当日/周环比/同比周/同比日)|单量(当日/周环比)|拖累环节|细拆/根因`。**大盘 + 分用户来源 + 分业务统一写 dau-净支付pv转化率（v7 改点：分业务从提袋率改为北极星，与大盘/来源同口径可比）**；仅分场景写提袋率（场景族分母是全站活跃DAU、dau转化率天然极低不可比）。转化效率列**增双口径同比两段「同比周/同比日」**（当日/周环比/同比周/同比日，v9-0714），对齐规则见下「日历/大促背景必标」。
  - **表2 流量**：`层级|对象|今日判定|流量(当日/周环比/同比周/同比日)|流量占比/曝光渗透率(当日/周环比/同比周/同比日)|走弱点|细拆/根因`。大盘 + 分用户来源写活跃DAU，并在第5列写**流量占比**（该来源活跃DAU/大盘活跃DAU，v6 改点2a，占比无同比列填 —）；分业务 + 分场景写曝光UV，并在第5列写**曝光渗透率**(当日/周环比/同比周/同比日，v6 改点2b + v9 双口径同比)。
  - **分用户来源必进两表（v5 改点1.2）**：4 类来源各一行，判据同大盘（转化率或单量环比越 ±15%）。
  - **指标名写进单元格（v5 改点2.1）**：如「dau-净支付pv转化率 1.31%」「活跃DAU 3,648,094」，表头**不再**单列北极星注解。
  - **细拆到品类根因（v5 改点2.2）**：业务行转化效率写 dau-净支付pv转化率（三位小数 X.XXX%），细拆列必须细到**品类**，再对主拖累品类下钻到**特征场景 / 漏斗环节 / 用户来源**定位根因（如「手机(单量29,428/-4.0%,下单率-2.9%为主拖累)」）。
  - **拖累环节=曝光渗透率必须细拆（v6 改点1）**：表1 里某业务拖累环节写「曝光渗透率」时，细拆/根因列**不能只写环节名**，必须点清是**哪些品类/场景/用户来源**的曝光渗透率（或曝光UV）在降、降多少（如「兴趣渗透率-5.4%集中在潮玩(-14.2%)/骑行(-11.8%)/鞋服(-9.0%)」）。任何"拖累环节"都同理——环节名之外要给出该环节下钻的最细走弱维度。
  - **流量占比/曝光渗透率两列口径（v6 改点2）**：表2 第5列——来源行=流量占比(该来源活跃DAU÷大盘活跃DAU，只写当日%)；业务/场景行=曝光渗透率(曝光UV÷活跃DAU，写当日%+周环比，周环比进彩表上色)。
- **措辞（v3-0711 改点1，硬约束）**：禁用晦涩/口语化词——不写「连乘自洽」「自洽偏差」「分业务三家」「塌方」等。漏斗四环相乘校验直接写「漏斗四环相乘与北极星一致（偏差在千分位内）」；三大业务直接写「消费电子/二奢/兴趣」。**文字精简，读者看到结论即可，不铺推导过程**（下钻推导压成一句话结论）。
- **结论先行（两句缺一不可）**：① 大盘——今天大盘核心指标是否异常，异常则点出 dau-净支付pv转化率/活跃DAU/单量 哪个异常、哪个环节、哪个维度；② 分业务——消费电子/二奢/兴趣**逐个点名**今日是否异常（正常/异常↓/异常↑），异常的点出 dau-净支付pv转化率 或 单量 环比幅度+拖累环节。
- **递进逻辑**：大盘是否异常（北极星环比）→ 分用户来源是否异常 → 分业务是否异常（消电/二奢/兴趣逐个判定）→ 分场景流量/转化是否降低 → 哪个环节（漏斗四环节归因）→ 特征维度（下钻到最细颗粒度）。四层级判定收进 §三 两张大表（表1效率/表2流量），环节/特征分列 §四/§五。
- **比率必带绝对量**：每个转化率旁注明 DAU/曝光UV/商详UV/单量。
- **比率写百分比（v2-1 + v7 北极星三位，硬约束）**：渗透率/到达率/下单率/支付率/提袋率等读 tidy 的 `*_pct` 列，写「X.XX%」两位小数；涨跌幅写「±X.XX%」，点数差用「±X.XXpp」。**唯一例外——dau-净支付pv转化率（北极星）统一写「X.XXX%」三位小数、涨跌幅「±X.XXX%」（全局强制规则，见 CLAUDE.md）**。北极星读 `dau_pay_rate_pct` 列时按三位呈现（`round(值,3)`），不要沿用两位。
- **口径透明**：北极星 = dau-净支付pv转化率（= 单量/活跃DAU，可跨维度比）；活跃DAU 为空的行如何处理如实说明。
- **只用中文指标名（v2-0710 改点2，硬约束）**：报告正文、表格、P2P 文本里**严禁出现英文字段名**（`dau_pay_rate`/`matched_dau_uv`/`pay_pv`/`exp_uv`/`detail_uv`/`order_uv`/`exp_penetration`/`detail_reach`/`order_rate`/`pay_rate`/`detail_pay_rate`/`bag_rate` 等）。这些只用于脚本与内部 CSV。对照表见 `assets/report-template.md` 头部注释：dau-净支付pv转化率、活跃DAU、单量、曝光UV/商详UV/下单UV、曝光渗透率/商详到达率/下单率/支付率、商详渗透率/商详转化率/提袋率。写完报告与 P2P 文本后 grep 一遍这些英文名，命中即改成中文再发布。
- **不在文字里直接写"北极星"（v11-0715 改点，硬约束，用户 2026-07-15 定）**：报告正文、章节标题（如「核心指标现状」而非「北极星现状」）、表头、结论段、图注、P2P 文本里**不用抽象词「北极星」指代指标**，一律写具体指标名——`dau-净支付pv转化率` / `活跃DAU` / `单量`。如「哪个北极星异常」写「dau-净支付pv转化率/活跃DAU/单量 哪个异常」，「北极星的波动」写「dau-净支付pv转化率的波动」，「漏斗四环相乘与北极星一致」写「漏斗四环相乘与 dau-净支付pv转化率 一致」。"北极星"仅可留在 skill/模板的作者注释里当概念标签，不进任何给业务看的成段文字与表格。写完报告与 P2P 文本后连同英文字段名一起 grep 「北极星」，命中即改成具体指标名再发布。
- **异动归因分层**：是"环比突变"还是"长期如此"，是"周内节奏"还是真异常。

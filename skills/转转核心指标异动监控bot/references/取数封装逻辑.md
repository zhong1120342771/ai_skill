# 取数封装逻辑（底表怎么来的）

> 这是底表 `hdp_zhuanzhuan_tmp_global.tmp_dws_zz_core_dataagent_zmt_v2_di` 的生产封装逻辑，**仅供理解口径**（货怎么分类、场景怎么归、DAU 分母怎么分维度匹配）。日常分析直接查底表即可，不要重跑这段。
> 建表 DDL 与全部 CTE 真源：`~/Library/Mobile Documents/com~apple~CloudDocs/转转/code/AAA全局底层/aaa全局脚本测试.sql`。
> 取数 SQL 模板见 `scripts/query_global_table.sql`。

## 一、底表 DDL

```sql
CREATE TABLE IF NOT EXISTS hdp_zhuanzhuan_tmp_global.tmp_dws_zz_core_dataagent_zmt_v2_di (
    tag_01  STRING COMMENT '口径',
    wd STRING COMMENT '维度',
    exp_pv int COMMENT '曝光pv',  exp_uv int COMMENT '曝光uv',
    detail_pv int COMMENT '商详pv', detail_uv int COMMENT '商详uv',
    order_pv int COMMENT '订单pv',  order_uv int COMMENT '订单uv',
    pay_pv int COMMENT '净支付pv',
    matched_dau_uv int COMMENT '该维度匹配到的DAU分母',
    matched_duan   string COMMENT 'DAU分母匹配到的端',
    matched_source string COMMENT 'DAU分母匹配到的用户来源',
    matched_type   string COMMENT 'DAU分母匹配到的资产分层'
) COMMENT '转转全局数据_分维度聚合（核心指标）'
PARTITIONED BY (dt STRING COMMENT '分区，格式yyyy-MM-dd');
```

## 二、封装链路（CTE 概览）

1. **`info`**（货的维度映射，真源）：从商品全量表按商品判定 `cate`（4 大业务：消费电子/二奢/兴趣/其他）与 `cate_02`（品类）。
   - 剔除：充配、直播代下单。
   - 业务归类：`消费电子`→消费电子；`二奢` 且 `business_line_id in (915051,915061)`→二奢（重奢）；其余 `二奢`/`长尾N`→兴趣；else→其他。
   - 品类归类：按 `cate_first/second/third_id` 一长串 case when（手机/平板/耳机/摄影摄像矩阵/游戏矩阵/笔记本/智能手表/包袋/腕表/饰品/鞋服…），兜底 `XX-其他`。

2. **`raw_funnel`**（漏斗明细，UNION 五段）：曝光 / 商详 / 下单 / 净支付（主口径含场景）/ 净支付（找靓机单独口径 `app_type in (79,78,141)`）。
   - 净支付：`is_pure_pay_the_day=1` 天内净支付、`is_exchange_order_flag=0` 剔换货。
   - 每段 join `info`（货）+ 用户属性（端/来源/资产），并按 `first_from/init_from/sec_from` 归类三级场景 `main_scene`/`scene_02`/`scene_03`（归类规则见 [维度体系与样例数据.md](维度体系与样例数据.md)）。

3. **`s1`**（21 个 tag_01 口径族聚合）：对 `raw_funnel` 按各口径族分别 `group by` 维度，算
   - `exp_pv/exp_uv`、`detail_pv/detail_uv`、`order_pv/order_uv`、`pay_pv`。

4. **`dau_cube`**（DAU 分母预聚合，本表核心）：把当日 DAU 按（端 × 用户来源 × 资产分层）**8 种组合**预聚合，未参与的维度置 `'ALL'`。这样每一种"细到什么程度"的维度组合都有对应的 DAU 分母格。

5. **`matched` + 完整性闸门**：对每条 `s1` 的 `wd`，按它实际含有的用户属性去 `dau_cube` 匹配最精确的分母格：
   - `matched_dau_uv = case when m.n_specific = r.required then m.matched_dau_uv else null end`
   - 只有当匹配到的分母格覆盖了 `wd` 里**全部**用户属性（`n_specific = required`）才保留分母；精确格缺失被迫跨维度回退（`n_specific < required`）则 `matched_dau_uv` 及 `matched_duan/source/type` **全部置 NULL**。

## 三、场景归类规则（复核场景口径看这里）

见 [维度体系与样例数据.md](维度体系与样例数据.md) 的 main_scene / scene_02 / scene_03 三级表；真源是建表脚本 `raw_funnel` CTE 里的 first_from/init_from/sec_from case when。

## 四、口径要点（务必带进分析）

- `matched_dau_uv` = **该维度匹配到的 DAU 分母（分维度可比）**，不是全局常数。`pay_pv/matched_dau_uv`（dau-净支付pv转化率）是**北极星**、可跨维度比大小。⚠️ 这与旧表 `uv_all`（全局常数、只表贡献占比）相反，详见 [字段映射与指标口径.md](字段映射与指标口径.md) §二。
- `matched_dau_uv` 为 NULL（每天约 6~8 行）时，该行不能算任何 DAU 类比率，**绝不当 0**，见 [字段映射与指标口径.md](字段映射与指标口径.md) §五。
- 净支付 ≠ 下单：`pay_pv` 是天内净支付（剔换货），比 `order_pv` 严格。
- 找靓机无曝光/商详场景细分，净支付走单独口径，场景恒为 `找靓机-不区分场景`。

## 一、底表的组织方式：`tag_01`（口径族） + `wd`（维度值）

底表用 `tag_01` 标记"这一行是按哪些维度交叉聚合的"，用 `wd` 给出该交叉下的具体维度值（`_` 拼接）。**先按 `tag_01` 锁定维度族，再在 `wd` 里筛具体值**——底表已经把各种组合都算好了，不用自己做笛卡尔积。

## 二、四大维度（人 / 场 / 货 / 端）枚举值

### 端（duan，terminal）
`转转APP`、`转转小程序`、`找靓机`
> 找靓机的净支付来自单独口径（`app_type in (79,78,141)`），场景恒为 `找靓机-不区分场景`。

### 人 — 用户来源（user_source）
`自然新增`、`新媒体新增`、`自然留存`、`新媒体召回`
> 新增=首次、留存=老用户回访、召回=流失后回来；"新媒体"指投放渠道来的。

### 人 — 用户资产分层（user_type，`$.B2C核心业务`）
`z0`、`z1`、`z2`、`z3`、`z4`、`z5`，业务上常并成三档：

| 档 | 层 | 含义 |
|---|---|---|
| 新用户 | z0 | 无交易 |
| 浅用户 | z1 / z2 / z3 | 浅层活跃 |
| 老用户 | z4 / z5 | 有交易行为 |

> 重点关心问题里点名的是 z1-z5（z0 为无交易新客，单独看）。
> **新用户口径**：`z0`（无交易新客）＝业务定义的「新用户」，与用户来源里的 `自然新增 + 新媒体新增`（首访口径）是同一批人的两个视角。问「新用户量级」取 z0 行或两个新增行的 `matched_dau_uv`，口径细节见 [字段映射与指标口径.md](字段映射与指标口径.md) §一·补。

### 场 — 场景（三个层级：main_scene / scene_02 / scene_03）

**main_scene**（`单维度-拆分场景`，由 first_from/init_from/sec_from 归类）：
`首页feeds`、`首页金刚位`、`首页栏目区`、`馆`、`大促三切分`、`商详同款推荐`、`搜索`、`找靓机-不区分场景`、`其他`

**scene_03**（`单维度-拆分scene_03`，更细）：

## 三、`wd` 解析规则（分析脚本按此拆列）

`wd` 用 `_` 拼接，但**维度值内部也可能含中文无分隔**（如 `品类二奢包袋` = 货前缀+业务+品类）。可靠的拆法是**按 `tag_01` 决定字段顺序 + 用枚举集合从尾部反向匹配**，而不是盲目 `split('_')`：

| `tag_01` 模式 | 拆解顺序 |
|---|---|
| `单维度-拆分X` | `wd` 本身就是那一个维度值 |
| `2维度交叉-端_业务/品类` | `<端>` + (`业务<业务>` 或 `品类<业务><品类>`) |
| `2维度交叉-端_用户来源` | `<端><来源>` |
| `3维度交叉-端_业务/品类_场景` | `<端>_<货>_<main_scene>` |
| `3维度交叉-端_业务/品类_用户来源` | `<端>_<货>_<来源>` |
| `3维度交叉-端_业务/品类_资产分层` | `<端>_<货>_<资产层 z0~z5>` |
| `4维度交叉-端_业务/品类_用户来源_场景` | `<端>_<货>_<来源>_<main_scene>` |
| `scene组合-*` 系列 | 前缀 `<scene_02>_<main_scene>`，再接端/货/来源/资产 |

货段以 `业务` 或 `品类` 开头：`业务X` → 业务粒度；`品类XY` → 品类粒度（X=业务名，Y=品类名）。

> `scripts/analyze_dimension.py` 已实现：用四大维度的**枚举值集合**（端/来源/资产/场景三层）从 `wd` 反向匹配切出各维度，剩余中间段按 `业务`/`品类` 前缀归到货。新增枚举值时同步更新该脚本的常量。
